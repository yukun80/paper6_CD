# 文档维护约定

[返回项目首页](../README.md) · [算法文档目录](README.md)

## 何时同步

讨论方案时正常讨论，不要求每轮对话修改文档。
方案确认并开始执行功能修改后，必须在同一次交付中同步更新受影响的说明及目录。
若修改不影响文档，在交付说明中简短说明原因。

## 内容放在哪里

- HarmoSSM 当前说明放在 [HarmoSSM 专区](harmossm/README.md)。
- CCDepth 当前说明放在 [CCDepth 专区](ccdepth/README.md)。
- 根目录及算法目录的 README 只保留概要和导航。
- 根 AGENTS.md 保留必要工作规则，不复制长篇操作说明。
- 既有历史方案、修订记录原位保留；通过各专区“历史资料”入口访问，不当作当前规范。

## 写作方式

中文为主，一篇解决一个问题，通常 50—150 行；超过 150 行优先按主题拆分。
简短目录无需凑足 50 行，完整命令、公式不为凑行数硬拆，历史原文不受长度限制。
每篇提供返回目录及相关章节链接，同一内容只维护一份。
命令写清执行目录、输入条件、输出位置和占位符；环境或数据缺失时明确说明。
涉及参数、数据要求、运行步骤、输出、恢复或验证方式的修改，应同步对应章节。
新增、移动或删除章节时同步调整相关目录和引用。

## 内容依据

以当前程序、配置和现存文件核对用法。无法确认的事实标记待核实，不把历史记录写成新验证结论。
帮助命令和轻量验证不能代替完整训练、真实场景精度或性能验证。
本次不新增文档检查工具、定期任务或提交限制。
